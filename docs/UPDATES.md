# Выпуск и обновление

## Канал

Публичный GitHub: https://github.com/michailr1/Model-Manager-LMM-

Используется Velopack 1.2.0 (SDK и CLI одной версии), канал `win-x64`, идентификатор пакета `LocalModelManager`. Установщик содержит .NET 8 Desktop Runtime. Релизы стабильные, версия — `X.Y.Z`.

Проверка запускается после открытия окна и каждые 6 часов. Ручная проверка также скачивает найденную версию. Приложение не перезапускается без нажатия кнопки. Неустановленная сборка не заменяет исходники и выводит объяснение. Скачанный пакет сохраняется между запусками; установка доступна без повторной загрузки.

Настройки: `%LOCALAPPDATA%\LocalModelManager.Settings\updates.json`. Они находятся вне каталога установки. Выбор другого публичного репозитория означает доверие его бинарным выпускам. Приватные токены в приложение не встроены. Ошибка конфигурации не включает автопроверку молча.

## Обычный выпуск

1. Внести изменение и проверить его; для нового поведения обновить документацию.
2. Повысить `<Version>` в `src/LocalModelManager.App/LocalModelManager.App.csproj`.
3. Создать `docs/releases/X.Y.Z.md` и обновить `CHANGELOG.md`.
4. Выполнить `dotnet build -c Release` и `dotnet test -c Release`.
5. Отправить изменения в `main`. Workflow **Publish Windows release** проверит проект, соберёт пакеты и опубликует релиз `vX.Y.Z`, привязанный к SHA сборки.
6. Дождаться зелёного workflow и проверить Assets и обновление с предыдущей установленной версии.

Workflow можно запустить вручную в Actions. Существующий опубликованный релиз повторно не перезаписывается. Если остался незавершённый draft, сначала выясните причину в Actions и проверьте его файлы; автоматическая перезапись отключена.

Публикация создаёт draft с полным комплектом файлов, затем делает его публичным. Поэтому клиент не видит релиз с частично загруженными пакетами. Для workflow достаточно встроенного `GITHUB_TOKEN` с `contents: write`, дополнительные секреты не нужны.

## Локальная сборка

```powershell
./scripts/Build-Release.ps1 -Version 0.6.0
```

Скрипт устанавливает CLI в `.tools`, собирает автономное приложение в `artifacts/<версия>/publish` и выпускает файлы в `artifacts/<версия>/releases`.

В GitHub Release нужно загрузить **весь** каталог releases, включая:

- `LocalModelManager-win-x64-Setup.exe` — первая установка;
- `LocalModelManager-<версия>-win-x64-full.nupkg` — пакет обновления;
- `releases.win-x64.json` — feed с размером и контрольными суммами;
- дополнительные файлы Velopack (`assets.win-x64.json`, `RELEASES-win-x64`, portable ZIP).

Одного ZIP с исходниками или Setup.exe недостаточно для автообновления. Полные пакеты выбраны для первого этапа; дельта-пакеты не собираются.

## Проверки и ограничения

Unit-тесты используют SDK Velopack с изолированным TestVelopackLocator: новая/текущая/старая версия, целостность загрузки, отсутствие пакета, настройки и недопустимые URL. Для полной проверки нужны два настоящих пакета и применение обновления.

Неподписанный выпуск может вызвать SmartScreen. Контрольная сумма проверяет целостность загрузки, но не заменяет подпись издателя. Доступ к публикации релизов следует давать только доверенным участникам. При отсутствии сети приложение продолжает работу; статус обновления показывает ошибку, повторная попытка возможна кнопкой или следующим циклом.

Официальные описания: [WPF и загрузка пакетов](https://docs.velopack.io/integrating/overview), [GitHubSource](https://docs.velopack.io/integrating/update-sources), [тестирование](https://docs.velopack.io/integrating/testing).
